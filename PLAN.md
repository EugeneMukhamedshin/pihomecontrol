# План доработки pihomecontrol (v2)

Уточнённые требования: насос — скважинный, бойлер — ТЭН, у обоих своя автоматика
(реле давления и термостат). Нужно **только удалённое включение/выключение** двух
контакторов. Пускатель котла тоже переведён на тот же API `switch` — и кнопка
в интерфейсе, и автоматика по гистерезису. Котёл остаётся на своей 3-фазной линии.

Поэтому «умные» политики из первой версии плана (выбег, сухой ход, расписание,
легионелла, приоритет по мощности) не нужны — они уже реализованы в штатной
автоматике устройств. Задача сводится к надёжному управляемому «рубильнику»
с честным состоянием в интерфейсе.

## 1. Что сделано в коде

### Новые файлы

| Файл | Назначение |
|---|---|
| `lib/hardware.js` | Слой GPIO: `pigpio` + `onoff` на Pi, заглушка при `GPIO_MOCK=1` |
| `lib/switches.js` | `RemoteSwitch` / `SwitchGroup`: включение, пауза, обратная связь, `state.json` |
| `lib/auth.js` | Вход по паролю: HMAC-cookie, `auth.json`, ограничение попыток — без внешних зависимостей |
| `public/login.html` | Страница входа |
| `devices.json` | Настройки контакторов: пины, полярность, пауза, dryRun |
| `tools/relay-test.js` | Проверка реле без нагрузки, определяет `activeLow` |
| `tools/smoke-test.js` | Автопроверка входа и API контакторов (до 16 проверок), работает и на ПК |
| `tools/install-service.sh` | Установка systemd-сервиса вместо pm2 |
| `tools/deploy.sh` | Обновление на Pi: `git pull`, `npm ci`, перезапуск, проверка `/login` |
| `deploy/deploy.ps1` | То же самое с Windows по SSH одной командой |
| `deploy/systemd/pihomecontrol.service` | Шаблон юнита (пути и пользователь подставляются) |
| `config/pihomecontrol.env.example` | Пример настроек сервиса: порт, пароль, cookie |
| `state.json` | Желаемое состояние (создаётся автоматически, в git не попадает) |

### Изменения в существующем коде

- `homecontrol.js`: инициализация `SwitchGroup`, события `switch` / `getDevices`,
  широковещательный `devices`; `SIGTERM`/`SIGINT`/`uncaughtException` гасят все выходы;
- **аутентификация:** страница и socket.io закрыты паролем; `lib/auth.js` проверяет
  пароль, ставит HttpOnly-cookie с HMAC-подписью и ограничивает попытки входа,
  проверка `Origin` не даёт подключиться к сокету с чужого сайта;
- **пускатель котла стал обычным устройством `SwitchGroup`** (GPIO27, обратная связь
  GPIO17): и автоматика, и кнопка в интерфейсе вызывают `switch`, работают пауза
  `minOffSec` и подтверждение от вспомогательного контакта;
- `config.txt`: безопасный разбор (NaN больше не отключает верхний порог),
  атомарная запись, нормализация при старте; при ошибке чтения файл не перезаписывается;
- датчики: CRC-проверка `w1_slave`, три ошибки подряд → значение скрывается,
  при недостоверной температуре нагрев выключается;
- `data/` создаётся при старте, CSV пишется по `__dirname`, а не по текущему каталогу;
- `PORT` из окружения (удобно для отладки), `Content-Type: text/html; charset=utf-8`;
- интерфейс: блок «Удалённое управление» с карточками и подтверждением команд;
- `public/homecontrol.html` перекодирован из UTF-16 в UTF-8 (иначе его нельзя
  нормально редактировать и diff'ить);
- удалён `heater.js` — он при запуске **включал** котёл и падал на неопределённой
  переменной `contactor`;
- `package.json`: `main`/`start`/`dev` теперь указывают на `homecontrol.js`;
- `.gitignore`: `data/`, `state.json`, `config.txt.tmp`.

### Как это работает

1. При старте каждый контактор принудительно выключается (безопасный старт).
2. Затем читается `state.json`; если устройство было включено и `restoreOnStart`
   не `false` — включается обратно. У котла `false`: он стартует выключенным,
   дальше решает гистерезис.
3. Кнопка в интерфейсе и автоматика отправляют одно и то же `switch {id, on}`;
   сервер проверяет паузу `minOffSec`, переключает GPIO и отвечает подтверждением
   или кодом ошибки.
4. Изменение рассылается всем открытым вкладкам; для котла ещё обновляются
   `contactorValue` и метрика `heater_on_gauge`.
5. При остановке сервиса выходы гасятся, но желаемое состояние в `state.json`
   сохраняется — после перезапуска вернётся как было.

Проверено в mock-режиме на ПК: запуск, вход по паролю (без cookie страница
редиректит на `/login`, сокет отвечает `E_UNAUTHORIZED`), выход, блокировка после
5 ошибок, включение/выключение всех трёх контакторов через `switch`, пауза 30 с,
работа гистерезиса через тот же `switch`, неизвестное устройство, неверный запрос,
восстановление состояния после перезапуска, отдача страницы в UTF-8. На реальном
Pi и с реальными реле **не проверялось** — это надо сделать на месте.

## 2. Полярность реле: что показывает код

В текущем коде нигде не используется инверсия:

- все `onoff`-входы и выходы создаются без `activeLow` — по умолчанию `false`;
- нагрев раньше включался через `heater.digitalWrite(1)`, теперь через
  `RemoteSwitch` с `activeLow: false`;
- `contactorValue` показывается как «On», если значение не 0.

То есть **код везде предполагает active-high: 1 = включено, 0 = выключено**.
Но это логика кода, а не факт про вашу плату: у большинства 4-канальных модулей
с оптопарой входы active-low. Проверить обязательно, иначе при старте «выключено»
может оказаться физически включённым:

```
GPIO: 0 ──► модуль active-high: реле выключено
GPIO: 0 ──► модуль active-low:  реле ВКЛЮЧЕНО
```

Порядок проверки (силовая часть отключена):

```bash
sudo node tools/relay-test.js
```

Скрипт по очереди подаёт 1 и 0 и печатает уровень. Щёлкнуло на «уровень 1» →
`"activeLow": false`; на «уровень 0» → `"activeLow": true`. После проверки
поставьте `"dryRun": false` для насоса и бойлера (глобально он сейчас `true`,
а у котла уже `false` — он подключён и проверен).

## 3. Вспомогательные контакты: зачем они

Вспомогательный (aux) контакт — это контакт внутри контактора, механически
связанный с силовыми. Замкнулся силовой — замкнулся и aux. Он не коммутирует
нагрузку, а «рассказывает» состояние.

Зачем может понадобиться:

1. **Отличить команду от факта.** Без него интерфейс показывает «включено»,
   даже если катушка сгорела, провод отвалился или выбило автомат управления.
   С ним видно: команда есть, а контактор не замкнулся → авария.
2. **Поймать залипание (сварку) контактов.** Команда «выключить», реле отпустило,
   а силовые контакты заварились — aux остался замкнут. Это единственный простой
   способ увидеть такую аварию дистанционно. Для бойлера на 2 кВт это актуально:
   термостат отработает, но контактор лучше не оставлять залипшим.
3. **Честный статус в приложении.** «Насос включён» будет означать «контактор
   замкнут», а не «я отправил команду».
4. **Диагностика при монтаже.** Сразу видно, доходит ли сигнал до контактора.

Чего aux-контакт **не** даёт:

- не показывает, работает ли насос: у него своё реле давления, контактор может
  быть замкнут, а насос стоять;
- не показывает наличие напряжения: если выше отключён автомат, контактор
  останется замкнутым (или не втянется — зависит от схемы);
- не заменяет защиту. Термостат бойлера и реле давления насоса остаются
  в цепи как независимая защита.

Как подключить (сухой контакт, без 230 В на GPIO):

```
3,3 В ──[10 кОм]──┬── GPIO25 (вход, подтяжка сверху)
                  │
aux NO ───────────┘
aux COM ────────── GND
```

При замыкании aux вход садится на GND (0), при размыкании — 1. В `devices.json`:
`"feedbackPin": 25` (и `26` для бойлера). Если aux коммутирует 230 В — только
через оптопару, ни в коем случае не напрямую.

Вывод: для двух устройств с собственной автоматикой aux-контакты **не обязательны**,
но это дешёвый способ не врать в интерфейсе и узнавать о залипании. Начать можно
без них (`feedbackPin: null`), добавить позже — код уже готов.

## 4. Что осталось сделать

### 4.1 Обязательное для эксплуатации

1. **systemd-юнит — сделано.** `deploy/systemd/pihomecontrol.service` +
   `tools/install-service.sh`: автозапуск после перезагрузки, `Restart=always`,
   `TimeoutStopSec=15` (успевает погасить контакторы по `SIGTERM`), порт 80 через
   `CAP_NET_BIND_SERVICE` без запуска от root, `SupplementaryGroups=gpio`.
   Настройки — в `config/pihomecontrol.env`, а `config.txt`, `devices.json`,
   `auth.json` и `state.json` при деплое не перезаписываются.
   Обновление и перезапуск — `tools/deploy.sh` (на Pi) или
   `deploy/deploy.ps1` (с Windows по SSH). Это заменяет pm2; старую версию
   нужно один раз остановить, чтобы освободить порт.

2. **Авторизация — сделано (простой вариант).** Любой в сети больше не может
   управлять котлом, насосом и бойлером: страница и socket.io требуют вход по
   паролю. Пароль и секрет подписи хранятся в `auth.json` (создаётся при первом
   запуске, в git не попадает) или задаются через `AUTH_PASSWORD` / `AUTH_SECRET`.
   Cookie — HttpOnly, SameSite=Lax, живёт 30 дней; 5 неудачных попыток с одного
   IP блокируют вход на минуту; подключение к сокету с чужого `Origin` отклоняется.
   Для выхода в интернет по-прежнему нужен HTTPS (nginx/Caddy) и
   `AUTH_COOKIE_SECURE=1` — сам сервер TLS не терминирует. Порт наружу не
   публиковать, только LAN/VPN.

3. **Проверка полярности и `dryRun:false`** (см. раздел 2) — на реальном железе.

4. **Проверка паузы насоса.** `minOffSec: 30` защищает от быстрых переключений,
   но если реле давления щёлкает часто, 30 с может быть мало или много — подобрать.

### 4.2 Гигиена репозитория

- удалить мёртвое: `server.js`, `app/`, `app.js`, `temp.js`, `config/config.js`,
  `Dockerfile` (или починить: `FROM node:20`, проброс `/dev/gpiochip0`, запуск
  `pigpiod` внутри контейнера — для GPIO это лишнее усложнение);
- убрать из `package.json` неиспользуемые зависимости: `mongodb`, `mongoose`,
  `influx`, `@influxdata/influx`, `bcryptjs`, `jsonwebtoken`, `express-session`,
  `compression`, `body-parser` — меньше поверхность атаки и быстрее установка;
- обновить `socket.io` (сейчас 2.x; клиент уже отдаётся своим сервером,
  внешнего CDN больше нет, но версия 2.x устарела);

### 4.3 Надёжность (по желанию)

- watchdog: `WatchdogSec=60` + `sd_notify`, либо реле с watchdog-входом;
- уведомления в Telegram при `E_GPIO`, недостоверном датчике и рассинхроне aux;
- счётчики моточасов и числа включений насоса — полезно для ресурса;
- метрики Prometheus по контакторам (`pump_on`, `boiler_on`, `switch_fault_total`).

## 5. Интерфейс

Переделан под телефон.

**Убрано:**

- ползунок мощности котла — значение остаётся в `config.txt` (первое поле, 2050);
- поля допусков — гистерезис фиксированный 0,5 °C, в интерфейсе не настраивается;
- чекбокс «Нагрев» заменён обычной кнопкой в блоке устройств.

**Сделано:**

- крупная текущая температура выбранного датчика и уставка: кнопки «−»/«+»
  по 62 px, шаг 0,5 °C, ручной ввод с цифровой клавиатурой (`inputmode="decimal"`);
- датчики — плитки со значениями. Выбирать можно только комнатные
  («Гостиная», «Кухня»); улица, кессон и труба показываются для контроля,
  но не выбираются, чтобы случайно не греть по уличной температуре;
- устройства: «Пускатель котла», «Насос», «Бойлер» — крупные кнопки, состояние
  и подтверждение пускателя, если подключён aux-контакт;
- статус: «онлайн / нет связи», «обновлено N с назад», предупреждение в dryRun;
- оформление: карточки, тёмная тема по системной настройке, крупные зоны нажатия,
  никаких внешних CDN (страница работает без интернета, socket.io отдаёт сервер);
  ошибки — тостом;
- проверено скриншотом в эмуляции 390×844 (Chrome DevTools): горизонтального
  скролла нет.

**Что осталось по интерфейсу:**

1. Ручной нагрев всё ещё перебивается автоматикой через 30 с. Если ручной режим
   нужен по-настоящему — делать `auto/manual/off`, а не кнопку.
2. Подтверждение для бойлера (2 кВт) — сейчас включается сразу.
3. График температур за 24 ч и журнал событий.
4. PWA-манифест, чтобы добавить страницу на главный экран.
5. Причина состояния: для котла «t 22,1 < 22,5», для насоса/бойлера — «вручную».

## 7. Риски

| Риск | Мера |
|---|---|
| Неверная полярность реле → нагрузка включается при старте | `dryRun` + `relay-test` до подключения 220 В |
| Залипание контактора | aux-контакт + уведомление (опционально) |
| Падение процесса | `SIGTERM`/`uncaughtException` → выходы 0, systemd `Restart=always` |
| Скачок напряжения на катушке | диод/варистор, отдельное питание модуля |
| Нет авторизации | Сделано: пароль, HttpOnly-cookie, блокировка подбора; наружу — только HTTPS/VPN |
| Порча `state.json` | атомарная запись; при битом файле старт с выключенных |
| Насос коротко циклится | `minOffSec`, при необходимости увеличить |
